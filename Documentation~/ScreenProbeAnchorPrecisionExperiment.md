# Native Gather 的 anchor 精度与收敛窗口实验

## 输入与判定范围

采用纯自发光 Cornell Box 的固定机位、1920×1080、16 px 探针网格、每探针 8 条射线。太阳与天空为零，近场 AO 关闭；方向引导、分层引导、guarded anchor 预滤波及四轮全分辨率 À-trous 开启。Surface Cache 固定为 8 阶、64 样本、32 批的已收敛源。未调整曝光、反射率或反弹增益。

这里同时检查固定误差、时间方差和最终被材质使用的线性 `E/π`。独立的 16,384 射线 / 探针参考来自同一渲染器，能分离有限采样与存储误差，但不是物理真值，也不是 Unreal 参考。不能仅凭 anchor 的 RMSE 下降就推广为画面降噪。

## 长序列重复性控制

实际重载 C# 和 shader 后，`ScreenProbeEpochLong-20261114-144706-279838` 的两组各 2,056 帧对照得到 **374 对 GPU 检查点，零 hash 分歧**。逐帧 4,112 条 CPU 状态没有缺帧、历史重置或源卡片更新；受检 2,783 份源码 / 实际脚本及两份外部输入未变。

这只说明该次重载后的控制可重复。此前长 A/A 失败的具体原因仍未定位，不能据此声称修好了生产同步或缓存失效。

## 128 帧窗口的实际 GPU 对照

`ScreenProbeAnchorStorage-20261114-151333-500182` 包含四组：两次原 FP16/128、FP16 covered-radiance 存储，以及 FP32/128。每组独立等待源缓存完成，重置 Gather epoch，预热 1,024 帧后连续测量 256 帧。A/A 的 **6,673 对实际 GPU 读回逐位一致**。

四组逐帧几何、当前帧 raw 输入一致，源 atlas 与统一参考 hash 一致；全部 5,120 条 CPU 记录中没有源更新或意外历史失效。实际四张 anchor / history / reconstruction 纹理的格式与请求一致。covered 存储与原方案的 coverage、统计纹理逐位相同，并确认它在 conditional RGB 的 FP16 舍入前保存 `C = L × coverage`。受检 2,784 份源码 / 脚本及两份输入未变。

最终像素的时间方差变化如下；**正值表示噪声变大**：

| 平面 | FP16 covered / 原 FP16 | FP32 / 原 FP16 | covered 平均能量变化 | FP32 平均能量变化 |
|---|---:|---:|---:|---:|
| 红墙 | +7.416% | +3.058% | +0.0732% | +0.0485% |
| 绿墙 | +5.756% | +4.405% | −0.0275% | −0.0467% |
| 后墙 | −0.543% | −0.742% | −0.5310% | −0.5352% |
| 地面 | +0.875% | +0.939% | −0.0617% | −0.0039% |
| 天花板 | **+29.709%** | **+18.036%** | +0.4854% | +0.3552% |

天花板最终方差为原方案 `0.0001057594`、covered `0.0001371795`、FP32 `0.0001248337`。covered 的最终像素相对 FP32 的 RMS 由 `0.01610` 降至 `0.01018`，说明其精度收益确实到达末端；但它没有降低实际时间噪声。

探针历史相对独立网格参考的 RMS 也有改善：天花板 `0.107695 → 0.098980`（FP32 为 `0.098897`），地面 `0.590852 → 0.570409`（FP32 为 `0.570622`）。该固定 / 数值误差收益与时间方差的退步同时存在，不将两者混为一项质量指标。

**结论：不推广 covered FP16 或单独 FP32/128 为降噪默认项。** covered 运行时原型已撤回，只保留 `Tools~/Diagnostics/Patches/ScreenProbeCoveredAnchor.patch` 与实测证据。原型关闭分支也曾相对更早的控制出现下游字节变化，因此没有声称其关闭分支逐位等于旧生产 shader。已撤回的代码不承担正常渲染路径。

## 更长窗口的后续检验

`ScreenProbeAnchorWindowCapture.cs` 另行对照原 FP16/128 两次、FP32/128 与 FP32/512。每组预热 4,096 帧，再观察 2,304 个实际渲染帧，每 9 帧保存一次，共 256 个统计样本。稀疏读回降低磁盘占用，逐帧 CPU 状态仍覆盖整段；raw / 几何在采样点计算 hash，仅保留少量完整载荷。

512 帧仅用于世界空间接收点移动不超过 0.1 mm 的诊断；移动时保留原有不超过 128 / 8 的衰减及全分辨率可见性拒绝。该限制不代替移动与光照变化验证。`ScreenProbeAnchorWindowExperiment.py` 使用 576 个渲染帧一块的四块条件重采样，并报告分段均值和短期相关性，以免把更慢的漂移当成收敛。

实际 `ScreenProbeAnchorWindow-20261114-155720-209141` 在长 A/A 阶段停止：两组各 6,400 帧，**6,420 对 GPU 检查点中有 6,154 对不同**。第 0 帧全部一致；首个保存到的分歧为第 4,095 帧，raw 有 3,234 / 16,320 个 texel 不同，最大分量差约 80.48。实际首次分歧可能在 1～4,095 帧之间，不能把检查点当作发生时刻。

两组所有采样点的几何与 VP 相同；第 0 / 4,096 / 6,399 帧的源 atlas 均与统一参考逐位相同。12,800 条逐帧 CPU 记录没有缺帧、源卡片更新或意外历史重置。2,784 份源码 / 脚本及两份输入 hash 未变。这些证据排除了所记录的输入变化，但没有定位生产路径中的实际原因。

**FP32/128 和 FP32/512 均未运行，不给出更长窗口的质量结论。** 512 帧运行时原型也已撤回，仅保留原补丁；已保存 Cornell Profile 仍为 128。下一步先用每帧小载荷 hash 定位 producer 首次分歧，再恢复精度 / 窗口比较，避免反复保存无效长序列。`ScreenProbeAnchorWindowExperiment.py` 会拒绝这次未通过 A/A 的捕帧，而不是生成看似有效的质量表。

首次已观察分歧的十份原始载荷另存在 `first-observed-difference/`，映射和 hash 为 `first-observed-difference.json`。原长序列中间读回按 [证据保留规则](GiEvidenceRetention.md) 归档；报告、CPU / hash 清单、源码 / 编译二进制、首尾及首次分歧保留，完整原序列不再可复算。

## 复现与限制

捕帧要求实际编译并重载对应诊断补丁；编辑器关闭自动刷新时，必须显式重编译 C# 并导入 compute shader。脚本核对已加载字段、实际纹理格式及逐帧状态，不能用磁盘源码 hash 代替 shader 已加载的证据。

```powershell
python -B Tools~/Diagnostics/ScreenProbeAnchorStorageExperiment.py E:/VividRP_GI_Evidence/ScreenProbeAnchorStorage-20261114-151333-500182
python -B Tools~/Diagnostics/ScreenProbeAnchorWindowExperiment.py WINDOW_CAPTURE
```

128 帧存储对照使用 Unity D3D12，相关实际 kernel 编译及 GPU 读回完成；长窗口对照则如上因 A/A 失败被拒绝。未运行 Unity Test Framework，因为 Editor 正在交互运行。没有本轮 GPU 计时结果，也未验证 Sponza。捕帧仅用临时 Profile，结束后确认场景未脏、相机 / Profile 已恢复，回调为空、override 为 −1、flags 为零。

撤回后 C# 重编译成功，显式导入正常 compute shader，确认已加载程序集不再包含 covered 或 512 原型。两个归档捕帧脚本的最终版本通过 Unity CLI `--dry-run` 仅编译检查；新增长窗口失败记录会同时写入 manifest 的 `errors`，不会只依赖 CLI 的外层异常。Python 分析器实际拒绝本次失败捕帧；这项拒绝检查不表示其未运行的 FP32 / 512 质量比较已验证。

后续 [producer 重复性控制](ScreenProbeProducerRepeatability.md) 已保留新的独立证据。旧存储实验在明确拒绝、检查引用后归档了中间载荷，首尾、汇总图与本文所引报告保留；不能再完整复算原序列。分析器会明确提示重新捕帧，而不将缺失原始数据当作成功。
