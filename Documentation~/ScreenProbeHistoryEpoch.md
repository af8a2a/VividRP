# Gather 历史起点与同像素阶段定位

本轮增加了“源缓存收敛后单独重置 Gather 历史”的诊断，确认初始历史残留能解释上一轮部分 scalar anchor 差异，但**没有解决原生路径的全部逐位重复性问题，也没有推广新的渲染行为**。随后在同一运行、同一像素 ROI 上采集 Resolve / Temporal / Final，观察到时域与小波继续降低方差；残余时间噪声在 Resolve 阶段已经存在。

起点 `b2d18c93`，证据根目录 `E:/VividRP_GI_Evidence/ScreenProbeHistoryEpoch-20261116-085700`。保持 Unity7000.0.0a16 / D3D12、纯自发光 Cornell 原机位、1920×1080、16 px / 每探针8 rays、原生 Gather、FP32/age512、像素上限32、4轮小波。Radiosity 固定8阶 / 64样本 / 32批，源 hash 仍为 `40252e7ae82c1da6ae025dbf012a3ce232aa54ea10bfbf1ca9a7998df93270a8`。本轮不修改 Runtime、shader、Profile或场景资产。

## 初始差异的衰减

上一轮 `uniform-corrected` 与 `transient-uniform-corrected` 的测量段 raw、方向历史与接收输入 hash 一致，天花板 anchor 却有初始差值。两端 GPU 统计均为 age512。按已有 EMA 公式，旧差值应每帧乘 `511/512`。

归档前对完整128帧的交互计算观察到逐帧递推最大残差约 `9.9e-8`。本轮正式可重算报告只使用仍保留的1024、1056、1088、1120、1151五帧，按真实帧间隔计算：跨间隔递推残差最大 `1.96e-7`，由首帧预测的最大误差 `4.06e-7`；差值范数比0.77977，公式预期0.78013。初始最大差值为0.00065729。

`old-initialization-tail.json` 明确 `fullRawSequenceAvailable=false`，不能把五帧重算说成完整128帧仍可独立复算，也没有定位最初产生差值的那一帧。这支持先控制初始历史，不能证明所有后续差异都来自初始化。

## 新起点的实际控制

`BuildScreenProbeHistoryEpoch.py` 复用既有质量采集链：

1. 清理实验相机状态，等待源8阶 / 32批连续八帧就绪。
2. 在相机帧已提交之后，按14个候选键逐项使已经存在的 Gather、屏幕照明及像素几何历史元数据失效；本次实际命中10类。核对必需的8类历史均存在；不销毁提交中的资源，不清除已收敛 Radiosity。
3. 从固定采样序号1733、epoch0开始。实际首帧检查 `m_HasHistory=false`、anchor统计历史无效、源更新数0；受检有效探针的 GPU age=1、位移/混合/历史状态为0。
4. 再预热1024帧，测量128帧；新起点后任何源失效都中止，不重新预热并将其隐藏。结束恢复 Profile / 相机 / 根对象 / hooks，并清理实验历史。

四个完成捕获都通过首帧与源控制，首帧 anchor/raw coverage相同，消费 RGB 误差通过既有FP16界限。原始持久化 trace shader始终用于渲染；没有安装上一轮黑色环境候选。采集脚本继承的未调用内存shader函数产生一条 `CS8321` 警告，不是渲染编译错误。最初 `uniform-a` 因局部函数声明顺序编译失败，未执行实验逻辑；修正后的独立目录为 `uniform-a-v2`，失败记录保留。

## 严格 A/A 仍未通过

## 默认引导对照的限制

`guided` 与均匀方向对照也完成了新起点控制，但1055帧有一次几何hash差异，故 `qualityAttributionQualified=false`。最终ROI方差点估计为天花板+33.64%、floor−44.57%、back−55.97%、边缘−43.71%；均值变化分别约+0.218%、+1.051%、−0.254%、+0.132%。单窗口、输入资格失败，不能据此把均匀采样推广为默认或将这些变化直接归因于引导。

探针条带与最终ROI的趋势甚至不同，但二者不是同一接收位置范围。因此本轮继续采集同像素阶段，而不是用条带对照宣称“噪声在校准或小波重新出现”。
