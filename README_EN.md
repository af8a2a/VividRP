# VividRP

English | [简体中文](README.md)

VividRP is a custom Scriptable Render Pipeline package for Unity 6. It follows the direction of the legacy [VividRP](https://github.com/af8a2a/VividRP), but the current codebase is no longer a direct match for the old README and its broad feature checklist. The current focus is to build a RenderGraph-first pipeline foundation that is runnable, extensible, and testable, then reconnect GPU Driven, Bindless, Ray Tracing, and related systems into a unified workflow over time.

> [!IMPORTANT]
> - The current development target is Unity `6000.5.0a7` / `6000.5`
> - The most reliable runtime path at the moment is Windows + DirectX 12
> - Bindless and Ray Tracing workflows are currently designed around DX12 / DXR
> - Features listed in the legacy README should not be assumed to be fully available in this package; use this document and the current source tree as the source of truth

## Current Positioning

Unlike the legacy README, which described VividRP as a custom URP variant, the current package is better understood as a standalone custom SRP package built around:

- `VividRenderPipeline` / `VividRenderPipelineAsset` / `VividRenderPipelineGlobalSettings`
- a `.vrdg` RenderGraph editor based on `com.unity.graphtoolkit`
- an importer pipeline that compiles `.vrdg` assets into runtime `RenderGraphData`
- a reflection-driven RenderGraph runtime executed through `PassRecorder`
- experimental subsystems around GPU Driven, Bindless, and Ray Tracing

## Implemented Today

### RenderGraph Workflow

- Create `.vrdg` assets through `Assets/Create/VividRP/Render Graph`
- A `ScriptedImporter` compiles `.vrdg` assets into runtime `RenderGraphData`
- Pass ports are generated by reflecting `[RenderGraphResource]` fields
- The editor currently supports `Texture`, `Buffer`, `RenderList`, `History`, `Preview`, and `Acceleration Structure` nodes
- `SubSystem` authoring is supported through Graph Toolkit Local Subgraphs
- Pass-owned resource override / hidden binding modes are supported
- The runtime includes history, preview, frame-context, and resource-binding management

### Core Rendering and Debugging

- Custom additional camera / light data and inspectors
- Core passes such as `PreDepth`, `GBuffer`, `CopyDepth`, `MotionVector`, `DeferredLighting`, and `FinalBlit`
- `HDRISky`, clustered lighting, and realtime area-light LUT preparation
- Debugging paths including `ClusterDebug`, `TileDebug`, `SliderDebug`, `OverlayDebug`, and `RTASInstanceDebug`
- The default Volume Profile is managed centrally through VividRP Global Settings

### GPU Driven / Bindless

- `GPU Driven` and `GPU Driven Debug Overlay` are already integrated into the pipeline asset inspector
- The package already contains meshlet collection import/build flow, the `MeshletRenderer` component, scene data builders, and visibility-buffer-related passes and shaders
- Bindless texture containers and a native descriptor allocator are already present
- `Setup-Bindless.ps1` is provided to copy `UnityBindless.dll` into `Assets/Plugins/...` so the plugin can load early enough

### Ray Tracing

- A serializable `RenderGraphAccelerationStructureDesc` is implemented
- Acceleration-structure resource nodes can be authored directly in the editor
- `RTASBuildPass` is implemented
- Directional ray-traced shadow and denoise passes are implemented
- `RayTracingSettingsVolume` exposes RTAS build / culling / bias settings
- The package already includes SIGMA shadow denoise shader resources

### Materials, Shaders, and Post Processing

- The package currently ships shaders such as `StandardLit`, `SimpleLit`, and `SimpleForward`
- URP Lit material conversion and custom shader GUIs are included
- Post-processing components already include Color Grading, White Balance, Channel Mixer, Split Toning, Film Grain, and Tonemapping
- `ThirdParty/LWGUI` is bundled for material inspector workflows

### Editor Tooling and Tests

- `PipelineResourceUpdater` and the `PipelineResourcesContainer` inspector centralize `[PipelineResource]` / `[ResourcePath]` recollection
- `Editor/RenderGraph/GeneratedRenderPassNodes.g.cs` is generator-owned and does not need manual maintenance
- `Tests/Editor` already covers a broad set of EditMode scenarios across RenderGraph, passes, drawers, GPU Driven, Ray Tracing volumes, material import, and component data

## Quick Start

1. Open the Unity project root that contains this package with Unity `6000.5.0a7` or a compatible `6000.5` build.
2. Create a `VividRenderPipelineAsset` through `Assets/Create/VividRP/Vivid Render Pipeline`.
3. Assign that asset in `Project Settings > Graphics` as the active SRP.
4. Create a `.vrdg` asset through `Assets/Create/VividRP/Render Graph`.
5. Double-click the `.vrdg` asset to open the RenderGraph editor, then add resource nodes and pass nodes.
6. Assign the generated `RenderGraphData` main object to the pipeline asset's `Render Graph Asset` field.
7. If you need a default Volume, initialize or edit it directly from the `Default Volume` foldout in the pipeline asset inspector.
8. If resource paths or `[PipelineResource]` declarations change, open `Runtime/Resources/PipelineResources.asset` and click `Recollect Engine Resources`.
9. Enable `GPU Driven` on the pipeline asset if you want to use the GPU-driven path.
10. If you need Bindless, run the following command from the project root, then restart Unity:

```powershell
powershell -ExecutionPolicy Bypass -File .\Packages\VividRP\Setup-Bindless.ps1
```

11. If you need Ray Tracing, use DXR-capable hardware in a DX12 environment and add `VividRP/Ray Tracing/Settings` to your Volume Profile.

## Not Restored From the Legacy README

Many advanced features listed in the legacy README are not the current delivered state of this package and should not be treated as available by default. Based on the current repository, the following directions are either incomplete or still mostly placeholders:

- Super-resolution stacks such as `DLSS`, `TAAU`, and `FSR*`
- The larger GI / SSR / Path Tracing / ReSTIR feature set mentioned in the legacy README
- Full implementations of subsystems such as `Decal`, `Terrain`, `Foliage`, and `Volumetric`
- A production-ready samples / demo-scene workflow

If you are looking for a feature based on the old README, check the current source tree, `Documentation/`, and `Tests/Editor/` first to verify that it actually exists in this package.

## Package Layout

- `Runtime/RenderPipeline`: pipeline assets, global settings, and Volume components
- `Runtime/RenderGraph`: runtime graph data, resource wrappers, preview/history systems, and the pass recorder
- `Runtime/RenderPass/Core`: the main core passes currently included
- `Runtime/SubSystem/GPUDriven`: GPU Driven, meshlet, bindless, and native integration code
- `Editor/RenderGraph`: Graph Toolkit editor integration, validation, importing, compilation, and node-registry generation
- `Editor/PipelineResource`: resource recollection and synchronization tooling
- `Shaders`: package shaders and shared HLSL
- `Documentation`: current workflow and subsystem notes
- `Tests/Editor`: EditMode tests

## Testing

Run the current EditMode suite from the project root:

```powershell
Unity.exe -batchmode -projectPath "<project root>" -runTests -testPlatform EditMode -testResults Logs/editmode-results.xml -quit -logFile Logs/editmode.log
```

There are no committed PlayMode tests in this package yet.
