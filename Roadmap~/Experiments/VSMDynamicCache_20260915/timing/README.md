# 动态缓存复用：场景跑测与阶段计时

日期：2026-09-15。代码：`352f0d4a1706e4e513bba9880b115ae8911466e9`（Expand VSM dynamic shadow cache reuse）。本次未修改运行时代码或着色器。

## 结论

**动态缓存的清页与重复判空收益已在 Sponza 场景测得。** 8192 下，静止动态对象的清页中位数由 **0.344 ms 降至 0.119 ms（约 65%）**；移动时由 **0.344 ms 降至 0.124 ms（约 64%）**。这些是清页阶段的降低比例，不是整帧 GPU 或帧率提升。

剩余成本也很明确：干净动态页仍有约 **0.12 ms 清页派发开销**；存在动态对象时，物体剔除仍约 **0.12–0.14 ms**；8192 的 `AllocationCommit` 在稳定驻留时仍约 **1.16–1.17 ms**。局部 bounds 失效在移动场景增加约 **0.033 ms**，需要计入复用成本。

## 1. 测量方法与控制变量

- Windows、Unity 6000.7.0a6 Editor / Edit Mode、RTX 5070 Ti、D3D12，主相机 1920×1080；场景 Sponza + SponzaLightingDay，原有 217 个 meshlet renderer。
- 4096 / 8192 虚拟分辨率，1024 物理页，128×128 纹素/页，静动态双池各 **16 层**。固定 4 条 SMRT 射线，临时关闭自适应减射线，保留原有页面压力控制。
- 三种状态：无额外动态投影者；相机前方 4 m 处的静止动态方块；该方块沿相机右方向以 32 个相机回调为周期移动，每步 0.025 m，范围 −0.4 至 +0.375 m，周期边界跳回。
- 每种分辨率/状态执行 **A/B/B/A**：A 每次主相机开始渲染时，仅将动态缓存有效位设为 false；B 正常运行。A 强制全动态池刷新，静态缓存照常复用；两者执行相同生产 16 层 caster。A 包含新增全动态失效 kernel 的约 0.002 ms，不能等同于旧提交的逐条命令计时。
- 24 个窗口，每窗口 **64 次预热 + 96 次采样**，共 1536 次预热和 2304 次采样相机回调。最终窗口记录中其他相机回调均为 **0**。
- 使用已有 `ProfilingSampler` 与 `ProfilerRecorder(GpuRecorder)` 采集阶段 GPU 时间。正常采样期间只保存预分配数组；窗口结束才读回元数据、压力、计数及间接参数并写文件。场景总 CPU/GPU 帧时未作为性能结论。
- Edit Mode 下以太阳强度 ±0.0001 微扰触发渲染，太阳方向与相机姿态固定。强度不属于阴影投影/cache key；静态 draw 维持约 0.007 ms，候选静止窗口动态 dirty 为 0。临时方块在相机回调中移动后显式调用组件原有变换同步方法，保证变化进入 PrimitiveScene。

GPU Recorder 返回的是延迟到达的最近 GPU 样本；相机回调序号不等于 GPU 帧 ID。保留所有观测，包括相同数值和尾部尖峰，不推定它们都是不同 GPU 帧。本次主要非空阶段的采样次数均为 1，未出现上一轮那种非空大任务仅有 256 ns 的异常窗口。空作用域的零值不用于计算收益；未锁定 GPU 时钟，未执行 Nsight Trace，本报告的时间来源为 Unity GPU Recorder。

## 2. 清页与判空

下表给出两个窗口 **p50 的范围**，单位 ms。脏页数是各窗口末帧快照，移动轨迹中不是每帧固定此数量。

| 分辨率 / 状态 | 驻留页 | 动态脏页 A → B | 清页 A → B | 判空 A → B |
|---|---:|---:|---:|---:|
| 4096 / 无动态物体 | 641 | 641 → 0 | 0.2611–0.2616 → 0.1199–0.1201 | 0.0739–0.0748 → 0.0026 |
| 4096 / 静止动态物体 | 666 | 666 → 0 | 0.2671–0.2673 → 0.1199–0.1201 | 0.0736–0.0737 → 0.0026 |
| 4096 / 移动动态物体 | 680 | 680 → 51 | 0.2698–0.2703 → 0.1299–0.1302 | 0.0750–0.0753 → 0.0532 |
| 8192 / 无动态物体 | 1024 | 1024 → 0 | 0.3442–0.3443 → 0.1190 | 0.0937–0.0963 → 0.0026 |
| 8192 / 静止动态物体 | 1024 | 1024 → 0 | 0.3441 → 0.1190 | 0.0932–0.0950 → 0.0026 |
| 8192 / 移动动态物体 | 1024 | 1024 → 34 | 0.3441–0.3443 → 0.1244 | 0.0945–0.0947 → 0.0669–0.0691 |

静止动态方块并非空池：候选末帧分别保留 **57 / 20 个非空动态页**。所有移动窗口的动态 revision 都增加 **320**，证明 160 个回调中的旧/新 bounds 已进入变更链；候选没有把移动误判成静止。

判空收益不会严格正比于脏页比例。现有 kernel 按首层非空信息证明页是否为空，受页内稀疏覆盖和线程组工作分布影响；移动时仍需重新扫描受影响页，不能把每个跳过页都折算为固定读取字节数。

## 3. 提交、覆盖、层插入及新增失效成本

| 分辨率 / 动态状态 | 动态实例槽位 A → B | 动态 draw p50 A → B（ms） | 动态失效 p50 A → B（ms） |
|---|---:|---:|---:|
| 4096 / 静止 | 454 → 0 | 0.0251 → 0.0069 | 0.0015–0.0017 → 约 0.0003 空作用域 |
| 4096 / 移动 | 902 → 89 | 0.0298–0.0300 → 0.0220–0.0223 | 0.0018 → 0.0092–0.0095 |
| 8192 / 静止 | 605 → 0 | 0.0195 → 0.0069 | 0.0018 → 约 0.0003 空作用域 |
| 8192 / 移动 | 1245 → 43 | 0.0343–0.0346 → 0.0160–0.0161 | 0.0018 → 0.0330 |

实例槽位来自窗口末帧的真实 indirect args，含展开与填充，不是有效三角形数。每实例 384 个顶点槽位：移动时分别由 **346,368 → 34,176**、**478,080 → 16,512**。此处没有统计 CPU API 调用数量；空实例仍可能保留间接绘制命令及绑定成本。

`DynamicRasterDraw` 包含几何处理、覆盖和原有原子层插入，不能作为单独的层插入时间。本次没有重新执行减层/跳过插入消融；此前的 [覆盖和层插入拆分](../../VSMRebuildCost_20260915/README.md) 是不同实验条件，不能与本表相减。生产插入与查询代码没有改变。

`DynamicRasterClear` 多数窗口为 0，4096 静止强刷窗口也只有约 0.00064 ms；它只划分 DSV 设置/清理命令，不能证明硬件清理免费，部分工作可能记入后续 draw。

局部 bounds kernel 仍由每个 bounds/clipmap 对应一个线程遍历页面矩形。8192 移动时的 **0.033 ms** 高于直接全量置 dirty 的约 **0.002 ms**，是实际观察到的复用代价；随对象数与覆盖面积扩大后的成本尚未测量。

## 4. 质量与预算是否一致

各 A/B/B/A 组的末帧四项分配计数完全一致，overflow 均为 0，primary 请求全部驻留：

| 分辨率 | 压力 bias | 无动态 / 静止 / 移动的 primary 请求=驻留 |
|---|---:|---:|
| 4096 | 0 | 641 / 649 / 640 |
| 8192 | 1.7419002 | 966 / 943 / 956 |

8192 已受压力策略降质；本表是在相同 bias、预算和请求条件下比较缓存，不表示两种虚拟分辨率提供相同空间细节。这里只记录窗口终点，不能当作逐帧预算轨迹。

计时结束后另行执行全深度对照，比较缓存产生的结果与同姿态强制动态池重绘：4096/8192 × 原位/向右 0.4 m/向左 0.4 m/禁用，共 **8 组**。姿态变化之间保留缓存，候选必须自行清除旧位置深度；强刷参考不清静态池、不改变页面映射。

- 两池完整 16 层合计 **3,546,808,320 个深度值**，静态与动态差异均为 **0**。
- 8 组物理页 owner 差异均为 **0**；每组检查数量大于 0。
- 有方块时动态池包含 193,433–995,528 个非零深度值；禁用后动态池非零值为 **0**。
- 这是冻结姿态、短位移/禁用后的深度等价检查，没有比较两套独立时域历史，也不覆盖连续骨骼变形、多相机或所有材质后端。

结果：[depth-oracle/results.json](depth-oracle/results.json)。大体积深度复制和比较在计时之外执行，其成本没有计入上述窗口。

## 5. 后续优化优先级

1. **稳定驻留仍支付的分配提交。** `AllocationPrepare` 约 0.0095–0.0102 ms，`AllocationCommit` 在 4096 静止约 0.601 ms、8192 约 1.164 ms，移动时约 1.169 ms；A/B 基本一致。动态复用完成后，这项仍明显大于动态清页。应单独检查稳定请求下的串行处理与实际缺页分配能否分开。
2. **用脏页列表驱动清页。** 源码仍对物理容量派发完整纹素网格，干净页在线程中读取元数据后退出；测得 0 dirty 时清页仍约 0.12 ms。下一步可评估按两池 dirty 列表做间接派发，同时保留完整 16 层清理。
3. **缩减失效与剔除固定成本。** 普通动态方块停止后，实例数归零，但动态物体剔除仍约 0.12–0.14 ms；移动时 bounds 失效最高约 0.033 ms。大量动态对象是否需要 bounds 合并或页列表并行化，应先增加对象数/覆盖面积扫描。

Unity Renderer 和动态 Skinned 仍会让整个共享动态池保守刷新，本次场景没有用它们验证选择性复用。上面是测量支持的后续方向，本次仅补测和归档。
