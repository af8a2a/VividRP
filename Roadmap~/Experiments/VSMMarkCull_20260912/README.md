# 当帧标页与页剔除测量闭环（2026-09-12）

起点：`68653a6c`。当前场景 Sponza，Unity 6000.7.0a6，RTX 5070 Ti，D3D12。

## 保留的改动

- `MarkVSMReceiverPage` 在当帧标记内核中合并 wave 内同一页的请求。仅当所有活跃线程指向同一页时 OR 本次迭代的角色并由一个线程提交；其余情况仍逐线程提交。保留全部接收者、完整 halo、主层／过渡／父层／末层优先级以及 `InterlockedMax` 帧龄语义。角色合并使用迭代局部变量，避免污染后续页。
- `VSMPrototypePrepareMeshletPageRequests` 改为单个 64 线程组并行扫描物理页 owner，以 groupshared 原子计数构建无序待绘制页集合。组内屏障后由一个线程准备绘制参数。CPU 派发、资源布局、caster 几何范围和相关页判断均保持原实现。
- 没有新增生产 C# 热路径、托管分配、buffer 或配置开关。没有更改 SMRT 求交、厚度、光程或采样规则。

Wave 操作的活跃线程语义依据 [Microsoft Wave Intrinsics](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/shader-model-6-0)；项目已有 DXC/wave 用法。本次 GPU 验证只覆盖该 D3D12 设备。

## 性能与取舍

4096 虚拟分辨率、1024 物理页、通用视域覆盖、4 射线 × 8 格预算、10 m／50 m 光程。每个窗口预热 4 s、采样 4 s，至少 120 个观测；按 10a、50a、50b、10b 顺序重复。图像抓取与性能采样分开执行。

| 指标 | 原始版本窗口中位数 | 最终版本重复窗口中位数 | 变化 |
|---|---:|---:|---:|
| MarkReceiverPages，10 m | 2.803–2.922 ms | 0.937–0.952 ms | 约 -67% |
| MarkReceiverPages，50 m | 3.448–3.537 ms | 0.991–0.993 ms | 约 -72% |
| PageCull，串行／并行页列表交叉复测 | 0.336–0.340 ms | 0.175–0.178 ms | 约 -48% |

完整过程保存在 `timing/` 和 `timing.csv`：

1. `mark-baseline_20260912_020306_356`：未修改基线。
2. `mark-wave_20260912_021116_040`：仅合并标页，初测 0.83–0.84 ms；PageCull 约 0.36 ms。
3. `mark-wave-cull64_20260912_021549_802`：并行页列表，PageCull 约 0.185 ms。
4. `mark-wave-repeat_20260912_022113_137`：回到串行版本交叉复测。
5. `mark-wave-cull64-repeat_20260912_022245_614`：恢复最终版本交叉复测。

首次标页 0.83 ms 与后续约 0.99 ms 存在运行间漂移，串行版本复测也出现该变化，因此采用最后窗口给出较保守收益。Resolve 的独立波动没有算入本次收益。

这些是 `ProfilerRecorder` 的 Editor GPU 阶段诊断，记录器标为 `completed_with_warnings`，不能视为已认证的整帧或选定相机性能结果。`PageCull` 嵌套在 caster culling 内，不能相加各阶段分位数。本次没有 Nsight 硬件瓶颈证据，不声称已确认缓存／带宽受限。

只读请求规模快照为容量 42,970、80 条绘制参数、17,780 个实际请求、单条最大 1,978。它说明容量派发有余量，但不是受控的分阶段剔除计数，本轮没有据此引入间接派发或扩大几何剔除。保留的是通过交叉复测和覆盖对照的并行 owner 扫描。

## 请求与覆盖验证

- `equivalence.json`：480 组独立 GPU 对照，343,800 个接收者输入，92,160 份页元数据逐位一致。参考 shader 为修改前快照，覆盖 PCF、密度选层、10／50 m SMRT、禁用请求、天空／稀疏活跃线程、随机深度和法线、奇数输出尺寸、滚动投影、帧 0／7／257 和已有未来帧龄。两侧均不绑定物理深度池或页表。
- `cold-frame.json`：3 组冷帧／重复帧／天空帧诊断；首帧和重复请求各 36 页，覆盖当帧分配、后续请求重发及天空清除。
- `culling.json`：56 组 GPU 对 CPU 页／meshlet 覆盖对照，预算 1、63、64、65、256、1024、4096，静态／动态、空／稀疏／全脏页、乱序物理 owner、小请求与大请求。验证每个相关页唯一、展开后的绘制集合、请求容量护栏，零不一致。
- 增加了合并请求的角色／帧龄回归及剔除工作组边界预算回归。它们仅完成编译，未启动 Unity Test Framework。
- `mark-kernel-bindings.txt`：最终标页内核只有 Globals、投影、当帧深度、GBuffer1 和页元数据 UAV，无页驻留或物理池依赖。

## 真实场景与边界限制

前后抓取为 `20260912_020409_820` 和 `20260912_022432_142`。静止 32 帧、平移 96 帧、转向 128 帧；每轮 90 个 GPU 快照。相机姿态、投影、jitter、SMRT 256 帧相位匹配，shadow layout 相同。每张阴影读回是 364,000 像素 ROI，不是全屏。

- 请求角色、分配状态、相对帧龄、分配计数、选层和混合权重均一致。
- 三组最大请求数为 668／670／675；缺页、溢出、最终不可用采样、最终 PCF 回退均为 0。两轮页表／owner 一致性审计无错误。
- 中间软阴影足迹失败仍存在（1204／496／695 次），由既有层级策略处理；前后次数相同，不能描述成所有单层足迹都成功。
- 静止组物理槽排列不同，平移／转向组的物理槽相同；移动组部分调试历史位不同。因此不声称原始缓存数据逐位相同。
- 32,760,000 个 ROI 像素观测中，前后 46 个差异超过 0.001，最大 0.25；三组 MAE 为 2.33e-8／2.70e-7／5.81e-7。不是逐像素零差异。
- 同一最终 shader 再抓取 `20260912_023249_826`，姿态／投影／相位仍匹配，重复间也有 35 个差异超过 0.001，最大 0.25。见 `repeatability.json`。这证明当前路径存在运行间边界波动，但不足以把每个前后差异归因于波动；几何归因仍未完成。

据此本轮保留精确请求合并和已通过覆盖验证的页列表并行化，没有引入新的几何近似。下一步应先固定边界像素的完整输入、物理深度和求交轨迹，区分缓存历史、浮点光栅与 SMRT 判定，再考虑更激进的剔除。
