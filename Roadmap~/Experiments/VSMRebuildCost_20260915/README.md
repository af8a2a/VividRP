# VSM 多层存储与持续重绘成本

日期：2026-09-15。关联：[VividRP / Unreal 差距分析](../../VSMUnrealGapAnalysis_20260915.md)。

## 结论

本轮保留静态、动态各 16 层深度，首先消除了大型 meshlet 请求在无关 clipmap 页面上的实例展开。同一诊断构建的交错 A/B 中，持续转动光源时 `VSM.StaticRasterDraw` 的窗口中位数下降约 **49–51%（4096）和 45–46%（2048）**。这不是整帧 GPU 提升比例。

16 层双池深度 payload 仍为 **2 GiB / 1024 页**，本轮没有降低存储容量。测量表明，在此场景的持续重绘中，无效提交的代价大于增加隐藏深度层的增量；先减少这些提交，可以在保持隐藏遮挡信息的条件下获得明显收益。

## 测量范围

- 已打开的 Unity 6000.7.0a6 Editor，Edit Mode；Sponza / SponzaLightingDay，RTX 5070 Ti，D3D12，1920×1080。
- 1024 物理页，128×128 纹素/页，双池各 16 层；分别测量 2048、4096 虚拟分辨率。固定 4 条 SMRT 射线，临时关闭自适应射线。
- 持续重绘轨迹：太阳偏航角按 16 帧循环，每步 0.025°；每个窗口 64 次相机回调预热、96 次采样。A/B 使用同一编译构建，通过诊断开关选择旧列表或分组列表；性能比例取这一组对照。
- 临时诊断逐项运行，结束后恢复太阳、相机、Volume 与后台运行设置；没有保存场景。原配置为 8192 / 1024，已恢复。
- 原始数据在 `timing/`、`group-timing/`；汇总在 [summary.json](summary.json)。Profiler 数据是阶段 GPU 时间；嵌套 marker 不能相加，各窗口中位数也不能拼成整帧中位数。

## 1. 清页、提交、覆盖和层插入

### 清页

| 阶段 | 4096 持续重绘 p50 | 2048 持续重绘 p50 | 解释 |
|---|---:|---:|---|
| `VSM.ClearPhysicalPages` | 约 0.47 ms | 约 0.27 ms | 清动态驻留页全部 16 层；静态仅清 dirty 页 |
| `VSM.PageCull` | 约 0.16 ms | 约 0.11 ms | 包含页面准备与请求剔除 |
| `VSM.StaticCasterCull` | 约 0.18 ms | 约 0.13 ms | 包含上面的 PageCull，不能重复加总 |
| 新增 `VSM.StaticRasterClear` | 记录为 0 ns | 记录为 0 ns | 不能证明 DSV 清理没有成本；fast clear / 延迟执行可能记入后续 draw |

另新增 `StaticRasterDraw`、`DynamicRasterClear`、`DynamicRasterDraw`，均使用缓存的 `ProfilingSampler`。它们将 DSV 设置/清理命令与 UAV 绑定、间接绘制命令分开，方便后续 GPU capture 定位。

### 提交与覆盖

原先每个大型 meshlet 请求都展开到所有 clipmap 的相关页面，再在顶点着色器中剔除其他层和投影范围外的页面。即使最终不产生片元，间接实例和顶点槽位已经提交。

4096 代表帧的实际 indirect arguments：

| 项目 | 原列表 | 按 clipmap 分组 |
|---|---:|---:|
| 相关页面总数 | 644 | 644 |
| 大请求固定展开步长 | 644 | 221 |
| 小请求实例 | 8,282 | 8,282 |
| 大请求实例 | 1,009,148 | 346,307 |
| 提交顶点槽位，384/实例 | 390,693,120 | 136,162,176 |

提交槽位减少约 **65%**。槽位包含被拒绝和 meshlet 填充部分，不能当作有效顶点数或三角形数。证据为 `group-timing/00_r4096_m0-args.json` 与 `04_r4096_m0-args.json`。

诊断中，让所有顶点立即返回拒绝位置，`StaticRasterDraw` 仍约 **23.06 ms**；仅拒绝大型请求约 **23.17 ms**；仅拒绝小请求约 **28.02 ms**。这支持“大请求展开与图形前端工作是主要负担”的判断，但没有硬件计数器，不能进一步断言具体前端单元饱和。

覆盖阶段目前只能用消融估计：保持几何和光栅、跳过深度插入时约 **24.82–25.06 ms**。与立即拒绝顶点的结果相比，剩余顶点处理及覆盖/片元启动还有明显开销；这些不同消融的差值不是可精确相加的硬件阶段时间。额外片元计数实验未执行，未给出未经测量的 overdraw 倍数。

### 层插入

| 插入消融 | 4096 p50 | 2048 p50 |
|---|---:|---:|
| 原 16 层 | 28.32–28.42 ms | 8.35–8.41 ms |
| 跳过插入 | 24.82–25.06 ms | 7.31–7.43 ms |
| 仅首层 atomic | 24.59–24.95 ms | 7.28–7.43 ms |
| 先读最末层拒绝 | 28.30–28.39 ms | 8.15–8.52 ms |
| 每层读取后跳过冗余 atomic | 27.80–27.92 ms | 8.00–8.07 ms |

在此诊断中，完整插入相对跳过插入的增量约为 3.3–3.6 ms / 4096，而不是全部约 28 ms。单层版本仅用于成本辨识，不能保持隐藏遮挡质量。读取后拒绝的收益不足以在本轮承担并发正确性与读取开销的额外复杂度，未采用。

最终 `VividVirtualShadowMapCaster.hlsl` 与修改前逐字节一致；生产深度插入、查询及 SMRT 算法均保留。

## 2. 最终实现

`VSMPrototypePrepareMeshletPageRequests` 在一个 64 线程组中计数每级相关页面，计算前缀偏移，再并行散射到连续列表。

```text
RasterPages[0]       = 每级相关页面数的最大值（大请求固定步长）
RasterPages[1..16]   = 各级页面数
RasterPages[17..32]  = 各级列表的绝对偏移
RasterPages[33..]    = 按级分组的相关虚拟页
```

大型记录由自己的 `pageRequest.w` 解出 clipmap，只遍历该级列表；超过本级页面数的填充实例直接拒绝。原有页内投影范围判断继续保留。

- 保持小请求、源 meshlet 请求容量、indirect command 数量与静动态页面相关性规则。
- 列表仅增加 **32 个 uint = 128 bytes**。没有新增逐帧 CPU 集合或字符串。
- 使用每级最大页数仍有填充实例；进一步按记录做精确展开/压缩属于后续优化，本轮未实现。

## 3. 性能结果与边界

| 虚拟分辨率 | 同构建旧列表 p50 | 同构建分组列表 p50 | draw 阶段降低 |
|---|---:|---:|---:|
| 4096 | 28.15–28.38 ms | 13.85–14.51 ms | 约 49–51% |
| 2048 | 8.19–8.20 ms | 4.38–4.52 ms | 约 45–46% |

移除诊断分支后的独立生产构建复测：持续重绘为 **14.67–15.08 ms / 4096**、**4.69–4.71 ms / 2048**。它确认生产实现仍有收益，但不与另一构建混算精确 A/B 比例。

静止缓存窗口的静态 draw 为约 0.008 ms，静态 dirty 计数为 0；但 4096 窗口的清页和 Resolve 分别出现约 19.96 ms、59.54 ms 异常高值。因此不以这一组声明全帧性能或完整静态路径无回归。补充复查未在合理时间内收集足够相机回调，已取消并恢复设置，没有完整计时窗口；取消记录保留在 `final-recheck/`。该异常尚未归因。

## 4. 隐藏遮挡质量与验证

### 深度池与当帧阴影等价

在 2048、4096 下分别比较静止机位、相机平移 0.3 m、太阳转动 0.15°、加入真实动态 meshlet 方块四个姿态。每个姿态先抓旧列表参考，再做旧列表重复控制和分组比较。动态方块使用项目实际 meshlet builder / renderer，确实写入动态池。

- 16 组比较，两池合计 **3,872,391,168 个深度值**：全部驻留页的 16 层逐值一致；owner 差异为 0。
- 生产 Resolve 在同一相机回调重放两次，使用相同当帧深度、法线、uniform、历史及随机输入，只替换参考/实际深度池；**33,177,600 个阴影像素**差异为 0。
- 动态方块场景的动态池非零深度数分别为 591,043 和 851,749，避免将空动态池误当作动态质量验证。
- 这是冻结姿态、同帧输入的等价验证，不覆盖两条独立演化的完整时域历史、连续骨骼动画或所有材质后端。

有效结果：[native-v2/results.json](native-v2/results.json)。第一次比较 kernel 因分歧流程内同步而编译失败、检查数量为 0，已作废；修正为全线程到达 barrier，要求非零检查数量后重新运行。早期插入专用 fixture 也因排列生成器未覆盖全部 15 个元素而作废，不作为最终质量证据。

### 编译与边界

- DXC：50/50 compute 入口、32/32 完整 caster VS/PS 变体通过。后者覆盖 page caster、alpha test、VT/bindless、VSM caster 开关组合。
- Roslyn：按 Unity Bee 原有 response file 编译 Runtime、Editor、Editor.Tests，输出重定向到临时目录；三个程序集均通过，存在原有警告。
- 独立 GPU 页面分组 fixture：1/4/16 级 × 7 种容量 × 静/动态 × 4 种映射/dirty 模式，共 **168 组通过**。验证分级集合、计数、连续偏移、最大步长及尾部哨兵。
- 稳定容量路径预热后调用 256 次，当前线程 `GC.GetAllocatedBytesForCurrentThread()` 为 **0 bytes**；这不是全渲染循环所有线程的零分配证明。
- 更新既有请求展开回归测试，检查分组头及精确的 meshlet/page/list 多重集合。Editor 正在运行，**未执行 Unity Test Framework**；需在关闭 Editor 后运行相关测试。

### 未解决的验证限制

控制台仍有历史出现过的 `GPUMeshletCulling/CSDownsampleOccluderDepth`、`HZBGenerate/KMain`、`ColorPyramid/KMain` 的 14 UAV 超过 8 错误，三份源文件不在本轮修改范围内，尚未归因。此前 [VSMMarkCull 报告](../VSMMarkCull_20260912/README.md) 已记录同类错误。本轮不宣称全管线控制台无错误。

额外“将生产深度池改为片元计数”的覆盖实验被自动审批拒绝：审批指出旧验证出现过 GPU device hung，替换深度写入有 Editor/GPU 中断风险。该实验没有执行；本报告使用已完成消融、提交计数及生产深度等价验证。

## 5. 多层存储下一步

当前固定双池 16 层的 2 GiB payload、动态驻留页每帧全层清理仍存在。优先顺序建议是：

1. 在保留本轮深度 oracle 的基础上，进一步压缩同级内无效大请求，减少剩余填充及投影范围外的提交。
2. 对动态池增加“上一帧实际写入/当前需要写入”的页级跟踪，验证新页、复用页、物体退出和静动态迁移后，减少反复清空空动态页的工作。
3. 再评估隐藏层的稀疏分配/溢出存储。容量、原子插入和读取地址需要共同设计，不能仅减少层数、使用首层 HZB 丢弃隐藏几何或截断射线来宣称等价节省。

归档 `harness/` 保存实验脚本而非自动化测试入口；含诊断开关的脚本依赖 `diagnostic-source/` 中的临时构建，不应直接在最终生产源上用于复现 A/B。`before/` 与 `source-final.json` 分别保存修改前代码和最终源码哈希。
